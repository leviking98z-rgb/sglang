# Qwen3.8 Flash Next serving on 32 H20

Eight independent TP4/EP4 replicas, two per 8-GPU node, using BF16, NEXTN with three steps and four draft tokens, FlashInfer linear-attention prefill, Triton verification, 8192-token prefill chunks, and static memory fraction0.82. A round-robin SGLang router exposes the OpenAI endpoint.

The engine is based on main commit `a4a6eddd25343905245db7a8b54bcf24d9483c8b` plus the existing tested changes and the GPU JPEG RGB fix in `62d4f8941a0d36d009a09ae86bee6647dcb2b871`. The model is pinned to revision `de4b8e4d43b917e7706784d8bb445c9af86a3540`.

Set `QWEN38_PROJECT` to the verified project root. Cache the venv, committed source and complete checkpoint under `/root/.cache/qwen38-runtime-<project-name>/` before launch to avoid cold imports and repeated weight reads over a cross-region shared filesystem. The runtime sets PYTHONPATH to the independently verified node-local source cache so a read-only reused venv cannot silently import another deployment's editable source. `cache_model_parallel.py` resumes already verified local shards, rechecks their SHA256, copies remaining files using four streams, and publishes the checkpoint only after all 131 shard hashes match the pinned HF LFS metadata. Stop and verify the original sequential cache writer before running its replacement; never run both writers on the same staging directory.

This deployment additionally enables `SGLANG_QWEN4_PLE_HOST_REGISTER_CHUNK_MB=256` and launches each replica with `--interleave-memory`. The opt-in allocator uses contiguous private, prefaulted, MADV_DONTFORK memory and bounded CUDA registrations. It preserves the existing host-pointer gather kernel and rejects devices whose mapped pointers differ. Registration ownership follows tensor storage through Parameter and tensor views; failures roll back completed registrations. Eight H20 ranks have passed simultaneous allocation of both real BF16 table shapes (`80000384 x 160` and `80001280 x 160`), cross-registration gathers, three CUDA Graph replays and exact cleanup, with 409604259840 host bytes held simultaneously. A separate small test injects a registration failure and verifies rollback. This resolves a deployment failure caused by fragmented high-order kernel metadata allocations; it is not a measured inference-throughput improvement.

Qualification includes per-worker deterministic chat, tools and history, thinking, complete SSE streams, PNG/RGB JPEG/grayscale JPEG, expanded vision usage counts, 32K retrieval, and a complete196604-token prompt with a65536-token output budget and four reserved MTP tokens. The next output token is rejected. Accepting that budget with a short generated answer does not test a65536-token generation. Synthetic fixtures do not replay completed evaluation questions.
